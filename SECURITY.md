# Security

## Data

- **Synthetic data only.** Every document, person, client and amount in `src/data/` and `public/pdfs*/` is generated by [`scripts/seed.ts`](scripts/seed.ts) and [`scripts/make-drive-pdfs.ts`](scripts/make-drive-pdfs.ts). No real personal data, no customer data.
- **Provenance by design (GDPR-sane).** Every settled fact in the ledger keeps its source documents, the rule that decided it, who vouched for it and when, so a person can audit or correct any answer. A person decides whenever the rules and the jury cannot, and can override any decision.
- **Embeddings run locally.** Search and question embedding use `Xenova/paraphrase-multilingual-MiniLM-L12-v2` in-process ([`src/lib/embed.ts`](src/lib/embed.ts)); document text is not sent to an embedding API.
- **Minimal context to the LLM.** The Agent view sends only the question and the top 5 settled facts to the model, never whole documents ([`src/app/api/ask/route.ts`](src/app/api/ask/route.ts)).

## Secrets

- The app stores no API key. LLM calls go through the locally authenticated `claude` CLI (fallback `codex`).
- The only configuration is public client-side values for the optional Google Drive connector, see [`.env.example`](.env.example). Real values live in `.env.local`, which `.gitignore` excludes (`.env*`).
- The Google Drive connector requests the `drive.readonly` scope only and keeps the access token in `sessionStorage` for the tab's lifetime ([`src/flow/sources/GoogleDriveConnect.tsx`](src/flow/sources/GoogleDriveConnect.tsx)).

## LLM calls

[`src/lib/llm.ts`](src/lib/llm.ts):

- Child processes are spawned with an argument array, never through a shell, so user input cannot inject commands.
- Claude runs with `--tools ""`, `--strict-mcp-config`, `--setting-sources ""` and `--disable-slash-commands`: the model can read the prompt and nothing else. Codex runs with `--sandbox read-only`.
- Every call has a hard timeout (killed with `SIGKILL`) and at most 4 run in parallel.
- Model output is parsed as JSON and every cited fact id is checked against the ledger; unknown ids are dropped, so the model cannot invent a source.

## Scope

This is a hackathon proof of concept meant to run locally: there is no authentication and the ledger API (`/api/ledger`) writes to a local `.cache/` file. A production version would sit behind SD Worx SSO with per-client access control on the ledger.
